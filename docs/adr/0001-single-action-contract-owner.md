## 2026-11-02 result candidates precede obligation decisions

Primary users need their complete creative intent to reach a coherent film;
operators also need explicit approval and bounded paid execution. The latest real
run `20261102_141949_061901` stopped before any video task: the author described
the target evading, but labelled that entity's result `incidental`. Lowering
required a target result already labelled `required`. The independent necessity
review, which was meant to decide this distinction, never received that shot.
It also never saw incidental claims from otherwise valid authors. This confirms
a phase/authority mismatch, not an absent action, video API error or genre issue.

Borrow the compiler separation between source expressions and resolved semantics.
Creation supplies observable result candidates. The existing independent review
resolves their obligation status against the user request and later dependencies.
Do not strengthen the prompt to make the author guess the reviewer's decision,
force all results to be final obligations, or silently drop results to bypass the
compiler. Retain every statement, including contradictory statements, for review.

New scheduled flexible shots get the existing pending-admission marker at the
binding boundary, before entity registration and compilation. The marker is not
author-controlled. CandidateState needs only `state`; a validated legacy
`importance` annotation is optional and remains in source diagnostics, but cannot
preapprove or hide a claim. Lowering places all actor/target claims in the existing
candidate outcomes and other claims in the existing candidate scene-change
container. The latter's `required` tag is only the existing review transport's
candidate representation while the shot is pending, not an effective obligation.
Independent admission covers all candidates and records directions without
deleting their generation content. Missing target facts and unknown entities
remain real input errors. Exact choreography cannot opt into this candidate mode.

Historical unmarked entity and relative-role formats retain their old partitioning
and fingerprints; saved videos and frozen contracts are not migrated. The new
wire context is v6-candidate-results and lowering diagnostics v2-candidates.
Changed in-flight planning inputs still stop via checkpoint identity, rather
than silently mixing protocols or issuing replacement calls. The final provider
preflight also checks that pending candidates have passed admission, before any
paid reservation, including callers using the generator directly.

This reuses existing capacities (16 claims, 14 scene projections), review calls,
source maps, time allocation, provider compilation and execution ledger. It adds
no dependency, genre-specific inference, automatic repair, retry or remote call.
Rollback concerns code only; original responses and workspaces stay intact.

Validation starts with an unchanged, source-hashed real record: it reaches the
second-shot request boundary once; since no second-shot response was captured,
replay stops there rather than inventing a complete real plan. Metamorphic tests
cover 81 label combinations across person/person and person/object interactions.
Independent annotated verdicts demonstrate that authored `required` can be a
direction and authored `incidental` can be a user requirement, with every source
claim preserved. Full offline planning/review/generation/FFmpeg traversals use
unlabelled creation for dance, parcel transfer and rope rescue, with actual
15-second media assembly and idempotent completion. Missing facts, invalid states,
forged approval, incomplete/rejected reviews and pending paid submissions remain
blocked. Test annotations and synthetic media do not establish model reliability,
motion quality, or acceptance of a real finished film.

## 2026-11-02 creation requirements are distinct from historical defaults

The same types generate response schemas and parse new returned content. The
redundant post-parse empty-story guard is removed; character uniqueness remains
a separate check with its own message. The fixed requested ending remains a
schema const and an independent local comparison.

This follows the ordinary command/read-model distinction: a tolerant reader for
old records is not the specification for creating a new record. The shared
historical models and pure compiler remain unchanged. This supports old
workspaces and imports without automatically supplying new story facts. New
event-authoring schemas, including the exact array interface, state requirements
that execution already enforced. Checkpoint schema fingerprints prevent
silently reusing or resubmitting incompatible requests. Original responses are
saved before validation even when a derived authoring summary is never formed.

No new dependency, model call, motion quota, timing rule or scene-specific
vocabulary is introduced. Optional effects, decorative continuity details and
metadata defaults are retained where downstream execution does not require
them. We reject globally making every legacy field mandatory, weakening the
downstream requirements, manually filling the captured missing facts, or
retrying until the model happens to return a complete example.

Acceptance includes immutable real-response replay; each missing/blank required

## 2026-11-02 spatial references use the execution identity boundary

repeated paid debugging. Maintainers need deterministic replay and a clear
distinction between model errors and compiler errors. The bounded goal is to
make authoring and execution agree about structured entity references across

## 2026-11-01 system audit: creation ownership and response integrity

The creator needs a complete film; the maintainer needs failures to be attributable
and recoverable without implicit resubmission. The repeated `continuity_props` in
the untouched 155023 response is one observed failure, not proof that deleting that
field or shortening a prompt guarantees generation. Cross-flow inspection found
two broader ownership problems: physical scene names were independently authored
per shot and later reconciled by another model; visible props and persistent props
were separately repeated without an explicit distinction in the producer interface.

For new flexible authoring, story-owned location IDs and one typed declaration of
each scene object's role compile to the existing AuthoredShot. This is the same
compiler principle used for durations and adjacent-motion links: the author owns
creative choices, while the program owns repeated structural projections. No
prose inference merges scenes or promotes decorations into obligations. The schema
is derived from existing types, removes only unreachable definitions, and is no
longer duplicated in the system prompt. Exact and historical contracts stay intact;
new checkpoint request fingerprints prevent silent reuse under a changed protocol.

The scope includes another proven systemic mismatch: intent, continuation and
visual review formerly allowed last-key-wins parsing although creation rejected
duplicates. A negative continuation judgment could be overwritten by a positive
one in the same response. They now reuse the existing unique-key decoder. Visual
review requires a complete response envelope before interpreting judgments. This
is transport integrity, not another cinematic rule, score or semantic authority.

Scene review now records the request and original candidate before validation,
then marks it applied only after checks and submitted-shot lock protection. A
pending candidate cannot bypass those checks on recovery; previously applied and
legacy successful records may continue using their established mapping. This
avoids implicit re-review of negative results without treating a captured response
as an accepted plan.

Acceptance includes unchanged real-failure replay, lossless prop-role projection,
same-location/new-location cases across several topics, cardinality boundaries,
actual SDK request/response tests, cross-stage negative-to-positive duplicate
attempts, incomplete replies, interrupted/rejected scene review, and full offline
production/export recovery. Synthetic model observations prove flow and protection,
not creative reliability or film quality. No extra model stage, retry, keyword
heuristic, provider change, dependency or paid generation is introduced.

The typed-schema approach is consistent with [Outlines' schema-driven generation](https://dottxt-ai.github.io/outlines/reference/generation/json/).
We did not install or copy it: a hosted gateway's decoder is not controlled by this
client. Provider schema options cannot alone prove lexical uniqueness or semantic
correctness. These remain explicit limits for subsequent real evaluation.

Planning, Seedance prompt compilation, semantic review, and retake diagnosis must compile from the Action Contract Module in `pipeline/causality.py`. We deepen the existing Module instead of adding a workflow framework because duplicated interpretations caused semantic drift, while a new DAG, multi-agent runtime, or provider abstraction would add a shallow interface without another real adapter.

## Consequences

Planning progress is durable independently of final storyboard admission. New
formal runs checkpoint intent, identity and each authored event shot (legacy drafts
at a coarser boundary). Recovery replays completed call results through the same
compiler and review; it never edits them or declares them accepted. Input/model
changes or damaged records block reuse. Started/failed calls do not become retry
permission. This small workspace-owned checkpoint is not a second semantic owner
or workflow engine. Historical partial diagnostics and missing frozen storyboards
are not reconstructed from it.

Production plan v6 separates exact choreography from performance guidance. The
intent interpreter selects fidelity; reference-motion execution forces exact mode,
and unspecified historical intent stays exact. Slots freeze fidelity and the raw
creative brief before generation. The Action Contract still owns all semantic
projections and evidence verdicts. `performance.py` contains only policy projection
and observed time arithmetic; it is not another planner or acceptance service.

Performance mode treats director-selected paths and absolute times as suggestions,
but still requires each cause/response/state change, its participants and scope.
The reviewer must return finite actual start/effect/reaction/end times; local checks
reject reversed causality, out-of-shot evidence, insufficient union interaction
duration and insufficient result-hold capacity. A separate creative-brief verdict
prevents treating an authored choreography as a substitute for the user's request.
Unknown evidence remains rejection. Sampling and model judgement remain uncertain;
no real rejected take is relabelled accepted by a policy change.

Observed-entry adaptation may change the first interaction's approach only under
the performance policy. The result is compared verbatim before persistence; later
beats, geometry ownership, endpoint and camera remain frozen. The source storyboard
is unchanged. Policy-specific provenance prevents reusing incompatible entry plans.

Prepared identity assets belong to the visual-input boundary, separate from motion
semantics. A bounded local manifest binds one image hash to one registered identity;
the formal generator loads it before the first shot and rechecks it before submission.
Actual request order determines image numbering. Missing/changed supplied assets
stop rather than falling back to text; unprepared runs explicitly use text bootstrap.
This adds no paid image-generation step or required modeling subsystem.

Legacy storyboard fields remain accepted at the persistence seam, but downstream Modules may not independently redefine action phases or evidence fields. Planned State, Observed State, and Canonical State remain separate, and only an accepted Take may advance Canonical State.

An Action Contract may contain multiple ordered Action Events. Each event compiles through the same physical-effect rules; prompt profiles and review consume that projection instead of interpreting a shot-level actor as the actor of every event. Time arithmetic remains in `action_timing.py`, while event evidence fields and verdicts belong to the Action Contract Module. A numeric motion-preparation Adapter must declare its own support limits and produce actual media; text event support does not imply numeric rig support.

Ordered events need not be disjoint turns. Explicit `flow_from_previous` connects adjacent movement with shared participants; only linked interaction windows may overlap, with ordered boundaries/effects and union time accounting. `response_kind` distinguishes impact, evasion and deflection without weakening an omitted legacy impact obligation. The same Contract owns these prompt semantics and flow evidence requirements across normal/safe submission and review. Planning supplies specific movement links; it must not increase strike count or reset actors merely to meet a quota. Existing numeric adapters still reject unsupported choreography.

New flexible authoring represents within-shot continuity as `link_previous`.
The ordered unit list already owns the predecessor, so the compiler binds that
edge rather than asking the model to describe its cause again in `carry`.
Concrete use of the preceding movement stays in `action`; independent movements
remain expressible. Cross-shot entry uses the existing open-motion state. Legacy
imports and exact authoring keep their old free-text handoff semantics. The output
is still the existing Action Contract, with no additional reviewer or retry stage.
This design prevents a second handoff field from introducing a future result as a
past cause; it cannot prove physical feasibility or artistic quality of an action.

Event-based production slots now use a private semantic authoring representation
(`action_authoring.py`) before the existing persisted contract. This is a compiler
input, not a second action authority: it contains no phase, absolute timestamp,
duplicate actor/target geometry, or separate action-bearing provider prompt. One
unit owns the cause and full reaction. The compiler allocates integer milliseconds
under the frozen production budget and projects the unit into the existing contract;
normal/safe prompting, review, continuation and paid submission remain unchanged.
It cannot infer missing physical semantics or exchange actor identities to repair a
draft. Event authoring freezes story identity once, then requests one response for
each program-owned shot slot, carrying the preceding shot forward. Shot IDs/count
belong to the program, and registered actors constrain the response schema. Each
slot is validated before requesting the next. There is no JSON/whole-draft rewrite.
The identity and shot schemas are sent as `response_format.json_schema` with
`strict: true`, not only included in instructions. `ark_output_schema` projects
the provider's documented keyword subset; local Pydantic checks retain numeric,
length and cardinality bounds. API rejection does not fall back to JSON mode.
An SDK HTTP transport test checks the actual outgoing body and rejects a provider
response that violates the schema. Strict formatting does not prove narrative meaning.
Identity, individual raw responses, compiled output and validation are saved separately. Legacy non-event
authoring and persisted workspaces retain their existing compatibility paths.

ProductionPlan is the authority for allowed shot coverage and framing. Legacy
duration-based coverage heuristics cannot demand a close-up/insert that the frozen
plan prohibits. Plan integrity, cause/reaction evidence and observed visual quality
remain independently checked. This resolves an unsatisfiable long-dense-action
constraint without inventing extra shots or changing the user's duration.

Production plan v5 allocates a declared payoff one complete cause/reaction event,
moving the remaining event quota into preceding conflict slots. Aggregate event
count, interaction duration, total runtime and result-hold budget are unchanged.
This avoids incentivizing an extra attack after the finishing action or counting a
fall as a reverse interaction. V3/V4 plans are rebuilt under their original version
when validating saved workspaces; they are not migrated on resume. Whitespace word
counts remain editorial advice for compiled multilingual event descriptions, since
the structured contract, not an English word quota, carries execution detail.
Likewise, repeated mood labels are advisory for structured events: visible narrative
state changes remain required, but a sustained emotional tone is not itself invalid.

Strict structure cannot establish that free-text action semantics are true. A live
plan still classified entry, falling and sheathing as interactions. V5 event plans
therefore receive an independent text-only semantic admission check in the formal
orchestrator, after structural readiness and before any video reservation. It reads
the same persisted beats, verifies every beat with registered source field references, and
checks continuity/outcome; it neither repairs nor regenerates the story. Reports
bind to the complete storyboard, model and reviewer version. Both passing and
failing cached reports are revalidated on recovery; mismatch stops. This is an
additional admission gate, not proof of model understanding or a second compiler.
Quoted evidence is projected by the program from those fields, never copied or
concatenated by the reviewer. Classification checks compare the declared activity
with its description; a correctly labeled transition/hold needs no interaction.
Historical completed exports and non-event/older plan paths retain compatibility.

### Independent outcome and temporal evidence boundary (2026-10-29)

Real Fast failures in workspace 20261029_171222_838382 showed that changing prose
to call choreography flexible did not separate chosen maneuver from required result.
New flexible authoring now carries entity/state outcomes, admitted by an explicit,
source-bound planning verdict. The same Action Contract compiler emits the execution
suggestion and a separate outcome-only event review projection. Continuation freezes
outcomes; safe recompilation preserves them. No keyword stripping or new choreography
generator is introduced. Old workspace policy and provenance are not migrated.

Performance-v2 reviews retain actual media duration, sample timestamps and observed
active intervals. Local arithmetic unions intervals and bounds start/completion using
neighboring observations. Temporal uncertainty interrupts review and preserves the
original submission; only definite content failure or definite insufficient duration
may reject a take. This uses the existing unavailable-review recovery path rather
than adding a parallel generation state machine. Sampling bounds do not certify
vision-model accuracy. Numeric validation, cache replay, same-submission preservation,
legacy fingerprint and non-combat cases are regression-tested offline.

### Role-bound results and classified scene changes (2026-10-31)

The real first-shot response in `output/20261031_195436_982933` passed the authored
model but failed compilation: a free entity/state list mixed actor/target outcomes
with weapon and environment states. Prompt instructions already prohibited this;
adding another instruction or retry would not align the representations.

Primary users are creators submitting a brief; maintainers need traceable, resumable
contracts without paid trial-and-error. New flexible authoring uses a typed
`resolution` with target/actor states bound by the compiler and separately declared
scene changes. Each change names a registered entity and explicitly selects
required or incidental importance. Several consequences can belong to one cause;
the compiler does not fabricate extra events, discard states, or infer importance.
The independent planning verdict must cite the classification and reject causal
contradictions, lost user requirements, and future dependence on optional details.

The existing story-identity call also freezes scene-entity IDs. The authoring schema
constrains targets and scene-result references to those IDs plus characters; local
binding enforces the same registry even if the provider ignores its schema. The
program derives per-shot prop registrations from references, with no extra LLM
call, fuzzy alias correction, or new object invented after a failed response.

`action_results.py` contains these shared types and pure projections; the Action
Contract remains the only execution/review authority. Required scene states join
the existing outcome projection, incidental states are permitted optional detail.
Continuation freezes required object results too; safe prompts may omit optional
details while retaining every required result. Cache fingerprints bind the new
data. This is a bounded contract extension, not another planner or workflow.
An additional boundary test exposed a 1600-character result-echo limit in
continuation. New role-bound entries (explicit `scene_changes`, including an empty
list) use observed-entry-v5-bound-results: the model returns compatibility, approach
and rationale only; execution keeps the program-owned complete result. It cannot
silently drop a long object result. Old entries retain their original v3/v4 protocol.

The change is confined to flexible choreography. Exact/reference contracts reject
classified scene changes rather than silently discarding them. Historical outcomes,
fingerprints and failed evidence are not rewritten. The old failed response is
still rejected; a separately labeled offline annotation demonstrates lossless new
encoding, not a successful model run. The reference-motion adapter remains a
single fixed-camera two-person contact preview, with no weapons or multi-shot
support; this change makes no claim of improving its geometry or video adherence.

### Authoring is source data, not pre-normalized execution storage (2026-10-31)

The later real run `output/20261031_223900_693234` failed again: creative mood prose
was treated as a short label, and additional primary-target statements were rejected
even though their owners and importance were explicit. These relational restrictions
were not guaranteed by the provider schema. More instructions or whole-draft retries
would leave the same ownership mismatch in place.

For creators the required outcome is a usable complete film; for maintainers it is
an auditable, bounded conversion that preserves requirements without paid trial and
error. The selected boundary admits bounded creative statements, then deterministically
lowers them into the one existing Action Contract. Every statement survives with its
exact owner, text and importance. Required primary statements enter outcomes; all
other/optional statements enter scene_changes. Lists represent claims, not a map that
overwrites repeated owners. At most 16 primary claims or 14 additional claims can be
emitted from the already bounded source. No sentence is truncated, deduplicated,
merged semantically, promoted or downgraded. Source-to-destination paths are diagnostic
evidence, not another acceptance authority. Semantic contradictions remain visible to
independent planning review and still block execution when reported.

Natural-language aesthetic descriptions use the existing prose-sized budget. IDs,
enum membership, foreign-key registration, list sizes and numeric bounds remain
separate. Existing well-formed outputs keep their representation and fingerprints;
old outcomes-only input retains unique-owner rules. Persisted failed runs are not
migrated or relabeled. Optional details about a primary participant are allowed as
optional claims, never silently converted into required primary results.

Unedited replay next exposed a global timing inconsistency: local compilation of
relative weights produced 10.481 seconds against a 10.5-second whole-film floor.
Weights are a preference, not an obligation for a language model to solve integer
allocation. The compiler now uses the existing largest-remainder allocator to spread
only the deficit across available passive slack, preserving duration, causes, order
and result holds. Earlier provisional timings may be reallocated after all shots are
authored. Infeasible capacity stops; neither tolerances nor the film's floor change.
Existing saved plans are not recompiled on recovery.

Rejected alternatives: deleting repeated fields loses statements; increasing one
label limit leaves the representation mismatch; another model repair step adds
uncertain rewrites and calls; replacing the workflow adds complexity without fixing
ownership. Acceptance requires untouched real-response replay through the formal
compiler, per-claim preservation/source maps, multiple non-combat domains, explicit
semantic rejection, resource/legacy boundaries, and actual local pipeline/export
tests. Mock semantic/visual verdicts prove transport and enforcement only, not model
accuracy, reliable choreography, or film quality. This slice is entirely offline.

Acceptance covers provider-schema structure, original failure preservation, valid
and invalid result ownership, complete required/optional projections, planning
rejection, continuation, cache invalidation, formal offline planning/resume across
several subjects, and legacy compatibility. Real semantic classification accuracy,
model reliability and final film quality remain empirical unknowns.

### 2026-11-01: 独立审定结果必要性，保留完整创作

真实232051任务的计划通过，但作者自选的屈膝、剑尖方向等状态成为逐事件硬义务；文字中的自由编舞不等于结果合同真的自由。主要用户需要按主题获得连贯影片，维护者需要知道每个拒绝条件的来源。一次失败不能证明视觉模型误判，也不能证明Fast无法完成目标。

新自然语言自由编舞稿标记为待审定候选。复用原有独立规划审查调用，逐条分类原结果：用户明确要求（逐字引用）、后续因果依赖（向前可解析的源字段）、最小功能反应、可替换表演建议。审查同时检查完整表演是否无无故复位，以及要求是否保留。混合必要结果与可选姿态的句子不自动删除、改写或整体降级；无法判明则在付费前停止。

程序保留源稿所有文字，只在执行副本存储建议的来源路径。共享结果投影负责生成、验收与续拍的必要状态；建议仍供生成采用，非主要对象的可选变化仍受明确范围约束。每个作用、目标反应、用户结局、身份、运镜、接缝和全片时长检查保持。原稿冻结供恢复及缓存校验，历史任务没有此标记则不迁移、不改判。

这是对必要性判定职责的修正，不是建立第二套验收分数，也不等于视觉运动控制。当前2D预演不支持持械连招和多镜连续控制，本轮未扩建、未接入付费动作参考。选择先复用现有调用与合同，避免把一个素材问题扩张为3D平台。真实语义分类准确度及动作流畅性仍需独立实际证据；离线服务替身只能证明传递、保护和恢复行为。

### 2026-11-01：审查来源与语义判断分离

真实文本任务144550中的审稿人把作者的结果陈述填成用户原文，同时将三项结果标为minimal=false，外层理由却称没有冗余。已证实的问题是自由文本evidence承担了用户引用、后续依赖地址、当前反应和解释四种职责；文字提示没有在接口上落实来源边界。尚不能据此认定三项陈述都合理，或将false改成true。

面向创作者的目标仍是保留要求并生成完整影片；面向维护者则是能定位拒绝原因、恢复任务而不重复消费。采用数据溯源和类型化接口的思路：复用同一次审查，程序提供来源目录，模型仅在当前分类允许的地址中选择reference，reason单独解释。user只能选用户原文片段，continuity只能选后续可读字段，response只能选当前动作或反应，direction使用null引用。原始全文始终保留；分段仅用于寻址，不抽取或改写需求。schema与解码消费同一目录，程序取回精确文本。

新协议v8以single_category、mixed_categories、uncertain明确表示必要性类别是否混合，避免minimal被误解为字数或细节数量。内部降为原有判定合同，后两者仍阻止执行；不修改结果、不整体降级、不新增审查轮次。通用分类说明与线协议字段说明分离，避免同时要求旧evidence/minimal与新reference/composition。

复用范围涵盖所有已有结果审定和分批恢复路径，包括传递物品、舞蹈和运动等场景；没有题材分支或新依赖。代价是请求包含来源目录，且长需求的引用片段不保证等同于语义单元。选对地址不保证蕴含关系正确，因此不撤掉语义判断。历史缓存沿原协议和原指纹读取，失败保持失败，不升级重审；新协议只作用于新审查。

验收覆盖原始失败不变、错误来源拒绝、合法映射、混合/不确定拒绝、多场景目录、长原文与异常类型、请求变更后的缓存失效、SDK单次调用和分批中断恢复。离线通过仅证明协议与流程行为；真实文本遵循率、人物一致性、动作流畅性及成片质量仍须实际证据。借鉴[W3C PROV的来源追踪思想](https://www.w3.org/TR/prov-overview/)，未引入其本体或声称标准兼容。
