## 2026-11-17 — reference scope is not temporal progress

The captured four-shot run copied roughly three seconds of dynamic footage at
successive boundaries while its reviewers approved handoff. The review input
only contained the prior two-second tail, excluding the copied opening. Source
hash diversity does not imply novel work. Reference availability also cannot own
the decision to extend versus generate a successor shot.

of source endpoint capability. Original references and bindings remain intact;
legacy operation dictionaries retain their prior meaning. Motion preparation
uses the recent tail, whereas boundary review receives bounded whole-clip history.
Independent near-copy dynamic-prefix measurement supplies negative evidence
before a positive model verdict or cached review can authorize handoff. No match

This is a bounded measurement and authority correction, not skeletal control of
Fast or proof that a new model output will comply. Existing dependencies suffice;
no new provider, model phase, retake loop, reference deletion or content rewrite.
Source hashes, cross-domain media lifecycle, normal/strict decisions and recovery
are verified offline; see docs/validation/sequence-reuse-offline-20261117.md.

## Consequences

Planning progress is durable independently of final storyboard admission. New
formal runs checkpoint intent, identity and each authored event shot (legacy drafts
at a coarser boundary). Recovery replays completed call results through the same
compiler and review; it never edits them or declares them accepted. Input/model
changes or damaged records block reuse. Started/failed calls do not become retry
permission. This small workspace-owned checkpoint is not a second semantic owner
or workflow engine. Historical partial diagnostics and missing frozen storyboards
are not reconstructed from it.

Production plan v6 separates exact choreography from performance guidance. The
intent interpreter selects fidelity; reference-motion execution forces exact mode,
and unspecified historical intent stays exact. Slots freeze fidelity and the raw
creative brief before generation. The Action Contract still owns all semantic
projections and evidence verdicts. `performance.py` contains only policy projection
and observed time arithmetic; it is not another planner or acceptance service.

Performance mode treats director-selected paths and absolute times as suggestions,
but still requires each cause/response/state change, its participants and scope.
The reviewer must return finite actual start/effect/reaction/end times; local checks
reject reversed causality, out-of-shot evidence, insufficient union interaction
duration and insufficient result-hold capacity. A separate creative-brief verdict
prevents treating an authored choreography as a substitute for the user's request.
Unknown evidence remains rejection. Sampling and model judgement remain uncertain;
no real rejected take is relabelled accepted by a policy change.

Observed-entry adaptation may change the first interaction's approach only under
the performance policy. The result is compared verbatim before persistence; later
beats, geometry ownership, endpoint and camera remain frozen. The source storyboard
is unchanged. Policy-specific provenance prevents reusing incompatible entry plans.

Prepared identity assets belong to the visual-input boundary, separate from motion
semantics. A bounded local manifest binds one image hash to one registered identity;
the formal generator loads it before the first shot and rechecks it before submission.
Actual request order determines image numbering. Missing/changed supplied assets
stop rather than falling back to text; unprepared runs explicitly use text bootstrap.
This adds no paid image-generation step or required modeling subsystem.

Legacy storyboard fields remain accepted at the persistence seam, but downstream Modules may not independently redefine action phases or evidence fields. Planned State, Observed State, and Canonical State remain separate, and only an accepted Take may advance Canonical State.

An Action Contract may contain multiple ordered Action Events. Each event compiles through the same physical-effect rules; prompt profiles and review consume that projection instead of interpreting a shot-level actor as the actor of every event. Time arithmetic remains in `action_timing.py`, while event evidence fields and verdicts belong to the Action Contract Module. A numeric motion-preparation Adapter must declare its own support limits and produce actual media; text event support does not imply numeric rig support.

Ordered events need not be disjoint turns. Explicit `flow_from_previous` connects adjacent movement with shared participants; only linked interaction windows may overlap, with ordered boundaries/effects and union time accounting. `response_kind` distinguishes impact, evasion and deflection without weakening an omitted legacy impact obligation. The same Contract owns these prompt semantics and flow evidence requirements across normal/safe submission and review. Planning supplies specific movement links; it must not increase strike count or reset actors merely to meet a quota. Existing numeric adapters still reject unsupported choreography.

New flexible authoring represents within-shot continuity as `link_previous`.
The ordered unit list already owns the predecessor, so the compiler binds that
edge rather than asking the model to describe its cause again in `carry`.
Concrete use of the preceding movement stays in `action`; independent movements
remain expressible. Cross-shot entry uses the existing open-motion state. Legacy
imports and exact authoring keep their old free-text handoff semantics. The output
is still the existing Action Contract, with no additional reviewer or retry stage.
This design prevents a second handoff field from introducing a future result as a
past cause; it cannot prove physical feasibility or artistic quality of an action.

Event-based production slots now use a private semantic authoring representation
(`action_authoring.py`) before the existing persisted contract. This is a compiler
input, not a second action authority: it contains no phase, absolute timestamp,
duplicate actor/target geometry, or separate action-bearing provider prompt. One
unit owns the cause and full reaction. The compiler allocates integer milliseconds
under the frozen production budget and projects the unit into the existing contract;
normal/safe prompting, review, continuation and paid submission remain unchanged.
It cannot infer missing physical semantics or exchange actor identities to repair a
draft. Event authoring freezes story identity once, then requests one response for
each program-owned shot slot, carrying the preceding shot forward. Shot IDs/count
belong to the program, and registered actors constrain the response schema. Each
slot is validated before requesting the next. There is no JSON/whole-draft rewrite.
The identity and shot schemas are sent as `response_format.json_schema` with
`strict: true`, not only included in instructions. `ark_output_schema` projects
the provider's documented keyword subset; local Pydantic checks retain numeric,
length and cardinality bounds. API rejection does not fall back to JSON mode.
An SDK HTTP transport test checks the actual outgoing body and rejects a provider
response that violates the schema. Strict formatting does not prove narrative meaning.
Identity, individual raw responses, compiled output and validation are saved separately. Legacy non-event
authoring and persisted workspaces retain their existing compatibility paths.

ProductionPlan is the authority for allowed shot coverage and framing. Legacy
duration-based coverage heuristics cannot demand a close-up/insert that the frozen
plan prohibits. Plan integrity, cause/reaction evidence and observed visual quality
remain independently checked. This resolves an unsatisfiable long-dense-action
constraint without inventing extra shots or changing the user's duration.

Production plan v5 allocates a declared payoff one complete cause/reaction event,
moving the remaining event quota into preceding conflict slots. Aggregate event
count, interaction duration, total runtime and result-hold budget are unchanged.
This avoids incentivizing an extra attack after the finishing action or counting a
fall as a reverse interaction. V3/V4 plans are rebuilt under their original version
when validating saved workspaces; they are not migrated on resume. Whitespace word
counts remain editorial advice for compiled multilingual event descriptions, since
the structured contract, not an English word quota, carries execution detail.
Likewise, repeated mood labels are advisory for structured events: visible narrative
state changes remain required, but a sustained emotional tone is not itself invalid.

Strict structure cannot establish that free-text action semantics are true. A live
plan still classified entry, falling and sheathing as interactions. V5 event plans
therefore receive an independent text-only semantic admission check in the formal
orchestrator, after structural readiness and before any video reservation. It reads
the same persisted beats, verifies every beat with registered source field references, and
checks continuity/outcome; it neither repairs nor regenerates the story. Reports
bind to the complete storyboard, model and reviewer version. Both passing and
failing cached reports are revalidated on recovery; mismatch stops. This is an
additional admission gate, not proof of model understanding or a second compiler.
Quoted evidence is projected by the program from those fields, never copied or
concatenated by the reviewer. Classification checks compare the declared activity
with its description; a correctly labeled transition/hold needs no interaction.
Historical completed exports and non-event/older plan paths retain compatibility.

### 2026-11-01: 独立审定结果必要性，保留完整创作

真实232051任务的计划通过，但作者自选的屈膝、剑尖方向等状态成为逐事件硬义务；文字中的自由编舞不等于结果合同真的自由。主要用户需要按主题获得连贯影片，维护者需要知道每个拒绝条件的来源。一次失败不能证明视觉模型误判，也不能证明Fast无法完成目标。

新自然语言自由编舞稿标记为待审定候选。复用原有独立规划审查调用，逐条分类原结果：用户明确要求（逐字引用）、后续因果依赖（向前可解析的源字段）、最小功能反应、可替换表演建议。审查同时检查完整表演是否无无故复位，以及要求是否保留。混合必要结果与可选姿态的句子不自动删除、改写或整体降级；无法判明则在付费前停止。

程序保留源稿所有文字，只在执行副本存储建议的来源路径。共享结果投影负责生成、验收与续拍的必要状态；建议仍供生成采用，非主要对象的可选变化仍受明确范围约束。每个作用、目标反应、用户结局、身份、运镜、接缝和全片时长检查保持。原稿冻结供恢复及缓存校验，历史任务没有此标记则不迁移、不改判。

这是对必要性判定职责的修正，不是建立第二套验收分数，也不等于视觉运动控制。当前2D预演不支持持械连招和多镜连续控制，本轮未扩建、未接入付费动作参考。选择先复用现有调用与合同，避免把一个素材问题扩张为3D平台。真实语义分类准确度及动作流畅性仍需独立实际证据；离线服务替身只能证明传递、保护和恢复行为。

### 2026-11-01：审查来源与语义判断分离

真实文本任务144550中的审稿人把作者的结果陈述填成用户原文，同时将三项结果标为minimal=false，外层理由却称没有冗余。已证实的问题是自由文本evidence承担了用户引用、后续依赖地址、当前反应和解释四种职责；文字提示没有在接口上落实来源边界。尚不能据此认定三项陈述都合理，或将false改成true。

复用范围涵盖所有已有结果审定和分批恢复路径，包括传递物品、舞蹈和运动等场景；没有题材分支或新依赖。代价是请求包含来源目录，且长需求的引用片段不保证等同于语义单元。选对地址不保证蕴含关系正确，因此不撤掉语义判断。历史缓存沿原协议和原指纹读取，失败保持失败，不升级重审；新协议只作用于新审查。

验收覆盖原始失败不变、错误来源拒绝、合法映射、混合/不确定拒绝、多场景目录、长原文与异常类型、请求变更后的缓存失效、SDK单次调用和分批中断恢复。离线通过仅证明协议与流程行为；真实文本遵循率、人物一致性、动作流畅性及成片质量仍须实际证据。借鉴[W3C PROV的来源追踪思想](https://www.w3.org/TR/prov-overview/)，未引入其本体或声称标准兼容。

### 2026-11-02：创作方向作为共享输入，不另建动作或验收所有者

目标是让创作者输入的风格与导演方法贯穿完整影片。原有自由 `style` 文本未进入意图选择，后期还会独立推断转场和默认音乐。采用设计系统中“语义选择与消费端投影分离”的思路：同一次意图解析保存可选 `creative_direction`，原文依据和取舍理由可追溯；12 种受控方法供 8 种风格与 8 位导演参考复用，而非每个题材或导演建立独立分支。

## 2026-11-04 — action meaning must be expressible before it can be validated

contracts and impact semantics do not acquire a new interpretation.
